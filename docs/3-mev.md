# After Swap хук: Захват MEV после swap 

## Цель

Основной референс — [arb-hook](https://github.com/sterlingcrispin/arb-hook). Он запускает арбитраж из `afterSwap`, но использует v4 target-пул и v3/Pancake reference-пулы, а прибыль оставляет владельцу. У нас все пулы Uniswap v4, а всю прибыль направляем LP target-пула.

`InternalizationHook` — единственный v4 hook в этой части. `RouteRegistry`, `V4RouteExecutor` и `ProfitDistributor` — вспомогательные контракты или библиотеки.

Настройка `InternalizationHook`:

- `route_limit` — максимальное число последовательных попыток маршрутов после одного пользовательского swap

## 1. RouteRegistry

Сюда записываются маршруты, найденные нашим [Rust-инструментом](1-rust.md) 

Для каждого маршрута сохраняются:

- target `PoolId`
- стартовая валюта
- `priority` — место маршрута в порядке ожидаемой прибыли, рассчитанном Rust
- упорядоченные `PoolKey` всех swap маршрута
- направления `zeroForOne`
- `amount_in` — фиксированный размер первого swap в минимальных единицах стартовой валюты. Rust записывает его заранее. Hook не ищет оптимальный размер on-chain
- `min_profit` в минимальных единицах стартовой валюты 



## Порядок проверки маршрутов

Hook не может исполнить несколько маршрутов, затем независимо сравнить их фактическую прибыль и оставить только лучший. Успешный swap сразу меняет временное состояние target и reference-пулов, поэтому следующий маршрут уже увидит другие цены.

Rust заранее сортирует маршруты по ожидаемой прибыли. Hook работает с ними последовательно:

1. Берёт маршрут с наивысшим `priority`
2. Пытается исполнить его
3. Если фактический `profit < min_profit`, попытка полностью откатывается
4. Берёт следующий маршрут
5. После первого успешного маршрута останавливается

`route_limit` — максимальное число таких последовательных попыток после одного пользовательского swap. Это не число независимых on-chain расчётов.

## 2. V4RouteExecutor

Исполняет один маршрут из `RouteRegistry` через `PoolManager`.

- исполняет только v4 swap
- использует только `PoolKey` и направления, сохранённые в `RouteRegistry`
- стартовая и конечная валюта маршрута совпадают
- после исполнения возвращает фактический profit в стартовой валюте
- если `profit < min_profit`, попытка отменяется без изменения состояния, а `InternalizationHook` может перейти к следующему маршруту

## 3. InternalizationHook

Реализует `afterSwap`.

После пользовательского swap hook:

1. Определяет target `PoolId`
2. Проверяет **trigger policy**
3. Последовательно пытается исполнить до `route_limit` маршрутов из `RouteRegistry`. Неудачная попытка откатывается и не меняет итоговое состояние. После первой успешной попытки изменённое состояние **коммится** вместе с пользовательским swap в одной транзакции
4. Останавливается после первого успешного маршрута
5. Передаёт фактическую прибыль в `ProfitDistributor`

## 4. Trigger policies

### 1) AlwaysTrigger (для тестов) 

После каждого swap пытается исполнить разрешённый маршрут.

Используется только в тестах. Для production не подходит: попытка может быть убыточной или потратить газ без прибыли.

### 2) SlippageTrigger

Выбирает число проверяемых маршрутов по фактическому движению цены target-пула после пользовательского swap.

Для этого hook также реализует `beforeSwap`: он сохраняет tick до swap. В `afterSwap` hook читает tick после swap и вычисляет:

`abs(tick_after - tick_before)`

Настройки:

- `small_tick_move` — верхняя граница малого движения цены
- `medium_tick_move` — верхняя граница среднего движения цены
- `medium_route_limit` — сколько маршрутов проверять при среднем движении цены
- `route_limit` — сколько маршрутов проверять при крупном движении цены и абсолютный максимум

Правило:

- `tick_move <= small_tick_move` — маршруты не проверяются
- `small_tick_move < tick_move <= medium_tick_move` — проверяется до `medium_route_limit` маршрутов
- `tick_move > medium_tick_move` — проверяется до `route_limit` маршрутов

На бектесте протестировать разные сначаения параметров.

## 5. ProfitDistributor

После успешного исполнения маршрута направляет всю фактическую прибыль в стартовой валюте через `PoolManager.donate` в target-пул.

- `lp_share_bps` и `treasury_share_bps` в первой версии отсутствуют
- donation получают только LP с активной ликвидностью на текущем tick

Если исполненный маршрут не принёс `min_profit`, распределение не происходит, потому что вся попытка отменяется.
